Préparer son environnement

On apprend PL/SQL en l'exécutant. Avant tout, il te faut une base Oracle, un outil pour lui parler et le petit schéma « ressources humaines » sur lequel s'appuient tous les exemples et exercices du cours.

  • disposer d'une base Oracle gratuite (en ligne ou en local) et t'y connecter avec un utilisateur dédié rh ;
  • créer les tables departements, employes, journal_erreurs, historique_salaires et la séquence seq_employes ;
  • activer l'affichage de DBMS_OUTPUT et vérifier ton installation avec DESC et le dictionnaire de données.

Docker pas à pas

Les variables APP_USER et APP_USER_PASSWORD demandent à l'image de créer un utilisateur applicatif dans la base enfichable FREEPDB1. L'image lui donne un quota illimité sur le tablespace USERS et le rôle DB_DEVELOPER_ROLE (23ai), qui couvre tout ce que le cours crée : tables, vues, séquences, procédures, packages, types, triggers. Tu travailleras avec lui plutôt qu'avec SYSTEM : on ne crée jamais ses tables dans un compte d'administration. C'est aussi l'utilisateur RH que tu verras apparaître dans certains messages d'erreur du cours (RH.EMPLOYES…).

Paramètres de connexion, quel que soit l'outil : hôte localhost, port 1521, nom de service FREEPDB1, utilisateur rh, mot de passe rh.

Piège : CDB ou PDB ?

Une base Oracle récente est une base conteneur (CDB, ici FREE) qui héberge des bases enfichables (PDB, ici FREEPDB1). Si tu te connectes au service FREE ou au SID FREE, tu arrives dans le conteneur racine : l'utilisateur rh n'y existe pas (ORA-01017: invalid username/password), et un CREATE USER rh lancé là en system échoue avec ORA-65096 (nom d'utilisateur commun invalide). Connecte-toi toujours au service FREEPDB1.

Sur une autre base (19c d'entreprise, utilisateur créé à la main), si un chapitre échoue sur ORA-01031: insufficient privileges (création de vue, de type…), demande le privilège manquant à l'administrateur, par exemple GRANT CREATE VIEW TO rh;.

Astuce : messages en anglais et accents

Les messages d'erreur du cours sont en anglais. Si ton outil les affiche en français (SQL Developer reprend souvent la langue de ton système), exécute ALTER SESSION SET NLS_LANGUAGE = AMERICAN; pour comparer plus facilement. Dans SQL*Plus en terminal, sans NLS_LANG en UTF-8, les accents (Inès, employés) peuvent devenir des ? : d'où la variable passée à docker exec ci-dessus. SQLcl et SQL Developer n'ont pas ce problème.

Activer la sortie

DBMS_OUTPUT.PUT_LINE écrit dans un tampon côté serveur. Le client ne lit ce tampon et ne l'affiche, à la fin du bloc, que si tu le lui demandes. Le réglage vaut pour la session : à refaire à chaque nouvelle connexion.

Bonjour depuis PL/SQL !

Dans SQL Developer, tu peux aussi ouvrir le panneau Affichage › Sortie SGBD (View › Dbms Output) et activer la sortie pour ta connexion. Live SQL et Database Actions affichent en général la sortie sans réglage ; si rien n'apparaît, exécute quand même SET SERVEROUTPUT ON.

Piège

Le / seul sur sa ligne n'est pas du PL/SQL : c'est l'ordre donné à SQL*Plus, SQLcl ou SQL Developer (en mode script) d'envoyer le bloc au serveur. Sans lui, dans un script de plusieurs blocs, le client continue d'accumuler les lignes suivantes dans le même bloc et rien ne s'exécute comme prévu.

Le schéma d'exemple

Une petite entreprise : quatre départements (dont un vide, très utile pour provoquer des erreurs), dix employés avec une hiérarchie, une table de journalisation d'erreurs et un historique des salaires alimenté plus tard par un trigger.

  DEPARTEMENTS {
    NUMBER dept_id PK

    NUMBER emp_id PK
    VARCHAR2 nom

    VARCHAR2 modifie_par

    NUMBER id PK

    NUMBER code
    VARCHAR2 message
    VARCHAR2 backtrace
  }

Modèle de données utilisé dans tout le cours.

Les employés sont insérés dans l'ordre hiérarchique : un manager doit exister avant ses subordonnés, sinon la clé étrangère manager_id lève ORA-02291 (clé parente introuvable).

Astuce

Garde ce script sous la main. Beaucoup d'exercices modifient les données : relance-le pour repartir d'un état propre. Les triggers posés sur employes (chapitre 10) disparaissent avec la table et seront à recréer ; procédures, fonctions et packages restent en place et se recompilent à leur prochain appel. En 23ai, tu peux écrire DROP TABLE IF EXISTS employes PURGE; pour éviter les erreurs du premier passage. Sur Live SQL, si une table a disparu à ta reconnexion, relance simplement le script.

Vérifier l'installation

DESC (pour DESCRIBE, une commande du client et non du SQL) affiche la structure d'une table. C'est le réflexe à avoir avant d'écrire un SELECT … INTO ou une variable %TYPE. Elle fonctionne aussi sur une procédure ou un package pour voir ses paramètres.

Name Null? Type ----------------------------------------- -------- ---------------------------- EMP_ID NOT NULL NUMBER(6) NOM NOT NULL VARCHAR2(50) PRENOM VARCHAR2(50) POSTE VARCHAR2(30) SALAIRE NUMBER(8,2) COMMISSION NUMBER(8,2) DATE_EMBAUCHE DATE DEPT_ID NUMBER(4) MANAGER_ID NUMBER(6)

Présentation SQL*Plus ; SQLcl et SQL Developer donnent les mêmes informations avec une mise en forme un peu différente. Note que EMP_ID est NOT NULL : c'est la clé primaire qui l'impose.

Le dictionnaire de données décrit tous tes objets. Les vues USER_* listent ce qui t'appartient (USER_TABLES, USER_SEQUENCES, USER_OBJECTS…), les vues ALL_* ce à quoi tu as accès, les vues DBA_* toute la base (privilège requis). Les noms y sont stockés en majuscules.

table : DEPARTEMENTS table : EMPLOYES table : HISTORIQUE_SALAIRES table : JOURNAL_ERREURS séquence : SEQ_EMPLOYES (prochaine valeur 200)

Sortie obtenue sur un schéma neuf, juste après le script. La boucle FOR … IN (SELECT …) (boucle FOR de curseur) est détaillée au chapitre 04. La colonne LAST_NUMBER tient compte du cache de la séquence : après quelques NEXTVAL, elle peut afficher une valeur plus grande que la dernière réellement distribuée.

Piège

WHERE table_name = 'employes' ne renvoie rien : sauf si tu les as créés entre guillemets doubles, les noms d'objets sont stockés en majuscules. Écris 'EMPLOYES'.

Exercice 1 · Premier contact

facile

Voir la solution
10 employés, masse salariale : 46900

Si rien ne s'affiche, c'est presque toujours que SET SERVEROUTPUT ON n'a pas été exécuté dans la session. Un agrégat sans GROUP BY renvoie toujours exactement une ligne : pas de risque de NO_DATA_FOUND ici.

Exercice 2 · Un département à la loupe

facile

Écris un bloc anonyme qui affiche, pour le département 20, son nom, sa ville, son nombre d'employés et le salaire moyen, au format Informatique (Lyon) : 5 employés, moyenne 4320.

Voir la solution
Informatique (Lyon) : 5 employés, moyenne 4320

La jointure externe est un réflexe utile : avec dept_id = 40, elle affiche RH (Nantes) : 0 employés, moyenne (la moyenne est NULL, concaténée comme une chaîne vide). Avec une jointure interne, le département 40 ne renverrait aucune ligne et le SELECT … INTO lèverait NO_DATA_FOUND (voir chapitre 05).

Exercice 3 · Tester une contrainte puis annuler

moyen

Le schéma impose un salaire strictement positif. Mets le salaire du stagiaire (109) à 0 et lis le message d'erreur. Augmente-le ensuite à 1500, vérifie la nouvelle masse salariale, puis annule tout pour revenir à l'état initial. Quelle masse salariale affiches-tu avant et après l'annulation ?

Voir la solution
ORA-02290: check constraint (RH.CK_EMP_SALAIRE) violated

Le premier UPDATE échoue sans rien modifier : un ordre SQL en erreur est annulé en entier (atomicité de l'instruction), sans toucher aux modifications déjà faites dans la transaction en cours. Le second passe la masse de 46 900 à 47 000. Comme aucun COMMIT n'a été fait, ROLLBACK ramène 46 900. Le schéma qui préfixe la contrainte (RH) est celui de ton utilisateur ; en 23ai, le message peut être suivi d'une ligne d'aide Help: https://docs.oracle.com/error-help/db/ora-02290/. Le rollback au niveau instruction est approfondi au chapitre 05.

Quiz

Questions d'entretien

Pourquoi travailler avec un utilisateur dédié plutôt que SYSTEM ?

Par moindre privilège : SYSTEM a le rôle DBA, donc une erreur de manipulation peut toucher toute la base, et un code qui fonctionne sous SYSTEM peut échouer en production faute de privilèges. Par isolation : un schéma applicatif regroupe ses propres objets, qu'on peut exporter, supprimer ou recréer sans toucher aux objets internes d'Oracle. Enfin, les comptes d'administration sont réservés à l'administration : Oracle déconseille d'y créer des objets applicatifs.

Quelle différence entre une CDB et une PDB ?

Depuis la 12c, une base conteneur (CDB) héberge une ou plusieurs bases enfichables (PDB). Chaque PDB a ses propres utilisateurs, schémas et données applicatives ; le conteneur racine (CDB$ROOT) porte le dictionnaire commun et les utilisateurs communs (préfixés C##). Les applications se connectent à une PDB par son nom de service. Depuis la 21c, l'architecture multitenant est la seule possible.

Comment retrouver rapidement la structure d'une table ou la liste de tes objets ?

DESC table dans l'outil client pour les colonnes ; sinon le dictionnaire : USER_TAB_COLUMNS pour les colonnes, USER_OBJECTS pour tous les objets avec leur type et leur statut (VALID/INVALID), USER_CONSTRAINTS pour les contraintes, USER_SOURCE pour le code PL/SQL stocké. Penser aux noms en majuscules dans les filtres.
