Préparer son environnement

On apprend PL/SQL en l'exécutant. Avant tout, il te faut une base Oracle et le petit schéma « ressources humaines » sur lequel s'appuient tous les exemples et exercices.

  • disposer d'une base Oracle gratuite (en ligne ou en local) ;
  • créer les tables departements, employes, journal_erreurs et historique_salaires ;
  • activer l'affichage de DBMS_OUTPUT dans ton outil.

Activer la sortie

DBMS_OUTPUT.PUT_LINE écrit dans un tampon côté serveur. Le client ne l'affiche que si tu le lui demandes :

Bonjour depuis PL/SQL !
Piège

Le / seul sur sa ligne n'est pas du PL/SQL : c'est l'ordre donné à SQL*Plus (ou SQL Developer en mode script) d'envoyer le bloc au serveur. Sans lui, un script de plusieurs blocs ne s'exécute pas ou s'exécute mal.

Le schéma d'exemple

Une petite entreprise : quatre départements (dont un vide, très utile pour provoquer des erreurs), dix employés avec une hiérarchie, une table de journalisation d'erreurs et un historique des salaires alimenté plus tard par un trigger.

erDiagram
  DEPARTEMENTS ||--o{ EMPLOYES : "emploie"
  EMPLOYES ||--o{ EMPLOYES : "manage"
  EMPLOYES ||--o{ HISTORIQUE_SALAIRES : "a"
  DEPARTEMENTS {
    NUMBER dept_id PK
    VARCHAR2 nom
    VARCHAR2 ville
  }
  EMPLOYES {
    NUMBER emp_id PK
    VARCHAR2 nom
    VARCHAR2 prenom
    VARCHAR2 poste
    NUMBER salaire
    NUMBER commission
    DATE date_embauche
    NUMBER dept_id FK
    NUMBER manager_id FK
  }
  HISTORIQUE_SALAIRES {
    NUMBER emp_id FK
    NUMBER ancien_salaire
    NUMBER nouveau_salaire
    DATE date_modif
    VARCHAR2 modifie_par
  }
  JOURNAL_ERREURS {
    NUMBER id PK
    TIMESTAMP date_err
    VARCHAR2 programme
    NUMBER code
    VARCHAR2 message
  }

Modèle de données utilisé dans tout le cours.

Astuce

Garde ce script sous la main. Beaucoup d'exercices modifient les données : relance-le pour repartir d'un état propre. Sur Live SQL, les tables disparaissent à la fin de la session.
