Records et collections

Les collections sont les tableaux de PL/SQL. Elles sont indispensables pour le traitement en masse (chapitre 09) et reviennent souvent en entretien sous la forme « quelle différence entre… » ou « que se passe-t-il si… ».

  • déclarer des records et les manipuler en bloc, y compris dans INSERT et UPDATE ;
  • choisir entre tableau associatif, table imbriquée et VARRAY ;
  • utiliser les méthodes COUNT, FIRST, NEXT, EXISTS, EXTEND, DELETE et parcourir une collection creuse ;
  • reconnaître ORA-06531, ORA-06532, ORA-06533 et NO_DATA_FOUND ;
  • interroger une collection en SQL avec TABLE() et la comparer avec MULTISET.

Records

Un record regroupe plusieurs champs de types différents, comme une ligne de table. On accède aux champs par la notation pointée (r.nom) et on peut copier ou passer le record entier en une seule fois.

Petit net : 3354

Un record entier dans INSERT et UPDATE

Un record de forme %ROWTYPE peut alimenter directement un INSERT … VALUES r (sans parenthèses) ou un UPDATE … SET ROW = r. Pratique pour dupliquer ou archiver une ligne.

1 ligne mise à jour
Piège : SET ROW réécrit tout

SET ROW met à jour toutes les colonnes, clé primaire comprise, même celles qui n'ont pas changé. Cela peut déclencher des contrôles de clé étrangère et des triggers UPDATE OF colonne inutiles. Le record doit avoir exactement la structure de la table : si on ajoute une colonne à la table, un record %ROWTYPE suit, un record RECORD écrit à la main non.

Piège

Lire un élément qui n'existe pas dans un tableau associatif lève NO_DATA_FOUND, la même exception qu'un SELECT INTO vide. Un gestionnaire WHEN NO_DATA_FOUND placé pour le SELECT attrapera aussi cette erreur, ce qui brouille le diagnostic. Teste avec EXISTS avant de lire.

Piège : FOR i IN 1 .. c.COUNT

Sur une collection creuse, cette boucle lit des indices qui n'existent pas (NO_DATA_FOUND) et rate les derniers. Utilise FIRST / NEXT, ou garantis que la collection est dense (cas d'un BULK COLLECT). Et si la collection est vide, FOR i IN c.FIRST .. c.LAST échoue avec VALUE_ERROR (ORA-06502) car les bornes sont NULL ; 1 .. c.COUNT ne fait alors simplement aucun tour.

En entretien

Si on te demande « comment parcourir une collection en toute sécurité ? », la réponse attendue est la boucle i := c.FIRST; WHILE i IS NOT NULL LOOP … i := c.NEXT(i); END LOOP;, qui fonctionne pour une collection vide, dense ou creuse, et pour un index chaîne.

Comparer des tables imbriquées

Les tables imbriquées d'éléments scalaires se comparent avec = et <>, comme des sacs (multisets) : l'ordre ne compte pas, mais le nombre d'occurrences oui. Les VARRAY et les tableaux associatifs ne se comparent pas ainsi (erreur de compilation PLS-00306).

A = B (l'ordre ne compte pas) V est vide C contient des doublons SET(C) : 2 éléments distincts (101, 103) est inclus dans A
Astuce : expressions qualifiées (18c)

Depuis 18c, on peut initialiser un tableau associatif d'un coup : l_t := t_compteur('DEV' => 2, 'DBA' => 1); ou un record : r := t_paie(emp_id => 1, brut => 3000, net => 2340);. Avant 18c, il fallait affecter chaque élément ou champ séparément.

Quiz

Questions d'entretien

Quelles sont les différences entre les trois types de collections ?

Le tableau associatif est purement PL/SQL, sans initialisation, indexé par entier ou chaîne, creux possible : c'est le choix par défaut pour un cache ou un BULK COLLECT. La table imbriquée doit être initialisée, peut devenir creuse et peut être un type SQL (colonne, TABLE(), MULTISET, comparaison avec =). Le VARRAY a une taille maximale, reste dense, conserve l'ordre et peut aussi être un type SQL.

Que signifient ORA-06531, ORA-06532 et ORA-06533 ?

ORA-06531 « Reference to uninitialized collection » : table imbriquée ou VARRAY utilisé sans constructeur ; correctif l := t_type();. ORA-06532 « Subscript outside of limit » : indice hors des bornes légales (0, négatif, au-delà de la limite d'un VARRAY). ORA-06533 « Subscript beyond count » : indice au-delà des cases allouées, il manque un EXTEND. Une clé absente ou un élément supprimé lève, lui, NO_DATA_FOUND.

Différence entre COUNT et LAST ?

COUNT est le nombre d'éléments présents ; LAST est le plus grand indice existant. Ils sont égaux pour une collection dense indexée à partir de 1, différents dès qu'elle est creuse. Sur une collection vide, COUNT vaut 0 et LAST vaut NULL.

Comment parcourir une collection dont on ne sait pas si elle est dense ?

Avec FIRST puis NEXT dans une boucle WHILE i IS NOT NULL. Cette forme gère la collection vide, les trous laissés par DELETE et les index de type chaîne. FOR i IN 1 .. COUNT n'est sûr que pour une collection dense commençant à 1, comme le résultat d'un BULK COLLECT.

Peut-on comparer deux collections ou y chercher un élément sans boucle ?

Oui pour les tables imbriquées d'éléments scalaires : = et <> les comparent comme des multisets (ordre ignoré), MEMBER OF teste l'appartenance, SUBMULTISET OF l'inclusion, IS A SET l'absence de doublons, et MULTISET UNION / INTERSECT / EXCEPT combinent deux collections. Rien de tout cela n'existe pour les tableaux associatifs ni pour la comparaison de VARRAY.
