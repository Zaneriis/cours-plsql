Records et collections

Les collections sont les tableaux de PL/SQL. Elles sont indispensables pour le traitement en masse (chapitre 09) et reviennent souvent dans les questions « quelle différence entre… ».

  • déclarer des records et les manipuler en bloc ;
  • choisir entre tableau associatif, table imbriquée et VARRAY ;
  • utiliser les méthodes COUNT, FIRST, NEXT, EXISTS, EXTEND, DELETE ;
  • interroger une collection en SQL avec TABLE().

Piège : FOR i IN 1 .. c.COUNT

Sur une collection creuse, cette boucle lit des indices qui n'existent pas (NO_DATA_FOUND) et rate les derniers. Utilise FIRST / NEXT, ou garantis que la collection est dense (cas d'un BULK COLLECT). Et si la collection est vide, FOR i IN c.FIRST .. c.LAST échoue : FIRST est NULL.

Collections en SQL

Un type créé au niveau schéma (CREATE TYPE) est connu du moteur SQL : on peut interroger une collection comme une table avec TABLE() et utiliser les opérateurs ensemblistes MULTISET.

Astuce : expressions qualifiées (18c)

On peut initialiser un tableau associatif d'un coup : l_t := t_compteur('DEV' => 2, 'DBA' => 1); ou un record : r := t_paie(emp_id => 1, brut => 3000, net => 2340);.

Quiz

Questions d'entretien

Quelles sont les différences entre les trois types de collections ?

Le tableau associatif est purement PL/SQL, sans initialisation, indexé par entier ou chaîne, creux possible. La table imbriquée doit être initialisée, peut devenir creuse et peut être un type SQL (colonne, TABLE(), MULTISET). Le VARRAY a une taille maximale, reste dense, conserve l'ordre et peut aussi être un type SQL.

Que signifie ORA-06531 ?

« Reference to uninitialized collection » : on utilise une table imbriquée ou un VARRAY qui n'a pas été initialisé par son constructeur. Correctif : l := t_type(); avant EXTEND.

Différence entre COUNT et LAST ?

COUNT est le nombre d'éléments présents ; LAST est le plus grand indice utilisé. Ils sont égaux pour une collection dense indexée à partir de 1, différents dès qu'elle est creuse.
